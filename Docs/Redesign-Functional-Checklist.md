## Назначение проекта

AutoMT — персональный веб-помощник по обслуживанию одного или нескольких автомобилей. Пользователь хранит свой гараж, указывает пробег и последнее выполнение регламентных работ, видит остаток до следующего обслуживания и отмечает выполненное ТО. Интерфейс рассчитан на компьютер и телефон.

Основной сценарий: зарегистрироваться → добавить автомобиль и исходные данные обслуживания → следить за ближайшими работами → зафиксировать выполненную работу → получить обновлённый расчёт.

| ID | Функция | Что нужно сохранить |
| --- | --- | --- |
| AUTH-01 | Регистрация и вход | Регистрация по имени и паролю, автоматический вход после регистрации, повторный вход, сообщения об ошибках. |
| AUTH-02 | Пользовательская сессия | Сохранение сессии, проверка её действительности, переход на вход без действующей сессии, выход из аккаунта. |
| AUTH-03 | Личные данные | Гараж и записи обслуживания относятся к конкретному пользователю; доступ к чужим данным ограничен сервером. |
| GAR-01 | Несколько автомобилей | Список личных автомобилей с маркой, моделью, годом, VIN, пробегом и фотографией либо заглушкой. |
| GAR-02 | Добавление автомобиля | Ручной ввод марки, модели, года, VIN и текущего пробега. |
| GAR-03 | Редактирование автомобиля | Открытие заполненной формы, изменение основных данных, сохранение и отмена. Через эту форму сохраняется и изменение пробега. |
| GAR-04 | Удаление автомобиля | Подтверждение с указанием машины, возможность отменить действие, обновление списка после удаления. |
| GAR-05 | Основной автомобиль | Назначение основной машины, её размещение первой и первоначальный выбор на главной. Первая добавленная машина становится основной автоматически. |
| GAR-06 | Фотография | Загрузка пользователем изображения для выбранного автомобиля, отображение изображения и заглушки при его отсутствии. |
| GAR-07 | Копирование VIN | Копирование VIN из гаража и главного экрана с обратной связью об успешном действии. |
| MNT-01 | Начальные данные обслуживания | При добавлении машины — список регламентных работ, ввод пробега последнего выполнения, исключение ненужных работ из первоначального списка, предварительный расчёт следующего выполнения. |
| MNT-02 | Выбор машины на главной | Переключение между автомобилями и загрузка соответствующего списка работ. Мобильный вариант требует исправления, см. ограничения. |
| MNT-03 | Список предстоящих работ | Карточки работ выбранного автомобиля: название, индикатор пройденного интервала, остаток пробега либо величина просрочки. |
| MNT-04 | Приоритет работ | Просроченные работы выше остальных, затем ближайшие, затем сортировка по оставшемуся пробегу. Визуальное различие состояний. |
| MNT-05 | Подробности работы | Раскрытие карточки: интервал, пробег последнего выполнения, список подходящих типов расходников. |
| MNT-06 | Фиксация выполненного ТО | Переход к форме для конкретных автомобиля и типа работы, ввод пробега выполнения, сохранение записи, возврат на главную и пересчёт следующего обслуживания. Передача типа работы сейчас содержит дефект, см. ограничения. |
| MNT-07 | Записи обслуживания | Сохранение новых записей без замены предыдущих. Главная получает запись с максимальным пробегом по каждому типу работы. Отдельного просмотра полной истории пока нет. |

| ACC-01 | Изменение имени | Смена имени пользователя с обработкой занятого имени и сообщением об успехе. |
| ACC-02 | Изменение пароля | Ввод текущего пароля, нового пароля и его повторения; проверка текущего пароля и совпадения нового с повторением. |
| ACC-03 | Удаление аккаунта | Подтверждение удаления, отмена и переход к регистрации после успешного удаления. |
| UX-01 | Адаптивные сценарии | Доступность функций на компьютере и телефоне, переходы между главной, гаражом и аккаунтом. |
| UX-02 | Состояния интерфейса | Пустой гараж с предложением добавить машину, индикаторы загрузки на главной и в гараже, сообщения об ошибках форм и обратная связь после действий. |

## Текущая логика расчётов

- Следующее выполнение = пробег последнего выполнения + интервал типа работы.
- Остаток = пробег следующего выполнения − текущий пробег автомобиля.
- Работа просрочена, если текущий пробег больше или равен пробегу следующего выполнения. При точном достижении порога показывается просрочка на 0 км.
- Ближайшей считается работа с остатком не более 3 000 км; просроченное состояние имеет приоритет.
- Индикатор = доля пройденного интервала, ограниченная диапазоном от 0 до 100%.
- Расчёт основан на километрах. Расчёта по календарным датам или прогнозируемой интенсивности поездок нет.
- В исходном наполнении БД пять типов работ: замена масла, воздушного фильтра, тормозных колодок, свечей зажигания и проверка охлаждающей жидкости. Всем задан одинаковый интервал 7 500 км. Это значение в коде проекта, а не универсальный регламент обслуживания автомобилей.

## Незавершённые сценарии и дефекты, которые нельзя считать готовыми функциями

1. **Быстрое изменение пробега.** На главной `updateMileage()` меняет только данные в памяти страницы, без запроса сохранения. В гараже кнопки вызывают `updateMileage(car.id)`, но в модуле гаража такого метода нет. Надёжный существующий путь сохранения — форма редактирования автомобиля.
2. **Сохранение запчастей.** Форма отправляет `type`, `brand`, `code`, а DTO ожидает `TypeId`, `Brand`, `Article`. Обработчик добавления ТО вообще не сохраняет `Parts`. На главной отображаются типы расходников из справочника, а не фактически использованные детали.
3. **Открытие формы выполнения ТО.** Ссылка на главной передаёт `item.id` — идентификатор записи обслуживания. Форма трактует его как идентификатор типа работы. Следует передавать `item.typeId`, иначе после расхождения идентификаторов выбирается неверная работа или форма не инициализируется.
4. **Мобильный выбор автомобиля.** В обработчике `currentCarIndex = index initMaintenances()` отсутствует разделитель выражений. Сценарий нужно исправить и проверить при переносе интерфейса.
5. **Индивидуальные интервалы.** В форме добавления можно изменить интервал, но в запрос сохранения он не включается. Сервер использует общий интервал типа работы. При редактировании машины существующие регламентные работы в форму также не загружаются.
6. **Полная история.** Записи хранятся, но API для главной возвращает только запись с максимальным пробегом по каждому типу. Отдельного экрана всей истории и операций редактирования/удаления записей нет.
7. **Пробег при сохранении ТО.** Введённое значение сохраняется в записи обслуживания, но не обновляет текущий пробег автомобиля.
8. **Изменение имени.** Новое имя сохраняется, но заголовок аккаунта использует значение, прочитанное при инициализации, и сразу не обновляется.
9. **Обновление фотографии.** После загрузки изображения клиент не запрашивает обновлённую карточку и не меняет её URL; проверять результат нужно после повторной загрузки данных.

Эти пункты фиксируют состояние реализации. При редизайне нужно сохранить пользовательские сценарии и устранить препятствия их выполнению.

## Идеи из документации, ещё не реализованные

Следующие возможности перечислены в документации, но не входят в подтверждённую текущую функциональность:

- Автоматическое заполнение марки и модели по VIN и проверка истории/ограничений по VIN.
- Автоматический подбор фотографии автомобиля; сейчас изображение загружает пользователь.
- Пользовательские напоминания, включая страховку, и внешние уведомления.
- Прогнозирование пробега, даты следующего ТО и расходов.
- Произвольные внеплановые работы.
- Экспорт и импорт JSON/CSV.
- Тёмная тема и локализация.
- Напоминание о давно не обновлявшемся пробеге.

## Чек-лист приёмки после редизайна

- [ ] Новый пользователь регистрируется, попадает в приложение и может повторно войти после выхода.
- [ ] Без действующей сессии личные страницы и данные недоступны.
- [ ] Пустой гараж предлагает добавить первую машину.
- [ ] Можно добавить минимум две машины, изменить их данные и сохранить изменения после перезагрузки.
- [ ] Начальные значения последнего обслуживания сохраняются и участвуют в расчёте.
- [ ] Основная машина отображается первой и выбирается при открытии главной.
- [ ] Переключение машины показывает её работы и пробег на компьютере и телефоне.
- [ ] VIN копируется, фотография загружается и отображается после повторного открытия.
- [ ] Изменение пробега сохраняется и меняет расчёты после перезагрузки страницы.
- [ ] Проверены состояния работы: более 3 000 км до порога, ровно 3 000 км, ровно на пороге и после порога.
- [ ] Карточка показывает интервал, последнее выполнение, расходники и корректную степень прохождения интервала.
- [ ] «Отметить выполненным» открывает правильный тип работы для правильного автомобиля независимо от идентификатора записи.
- [ ] Сохранённое ТО меняет следующий порог и оставляет предыдущие записи в БД.
- [ ] Для вводимых расходников отдельно проверено реальное сохранение и последующее чтение; сейчас это требует доработки.
- [ ] Удаление машины можно отменить; после подтверждения список обновляется.
- [ ] Работают смена имени и пароля, выход и подтверждаемое удаление аккаунта.
- [ ] Действия с одним аккаунтом не раскрывают и не изменяют автомобили другого.
- [ ] Основные сценарии доступны с телефона; состояния загрузки, пустых данных, ошибок и успеха понятны.
